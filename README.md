# ShortestPath — 최단 경로 탐색 과정을 보여주는 지도 서비스

> 출발지와 도착지 사이의 최단 경로를 제공하고, 양방향 탐색 알고리즘이 경로를 찾아가는 과정까지 지도 위에서 시각화한 웹 애플리케이션입니다.

## 프로젝트 소개

경로 탐색엔진이 탐색한 경로를 시각화 해주는 웹 어플리케이션 입니다. 최종 경로뿐 아니라 **정방향 탐색, 역방향 탐색, 양쪽 탐색의 중첩 구간**을 서로 다른 색상으로 표현하여 양방향 경로 탐색 과정을 직관적으로 확인할 수 있도록 만들었습니다.

사용자는 지도에서 출발지와 도착지를 지정해 경로를 검색하고, 경로의 방향 전환 지점과 탐색 시간을 확인할 수 있습니다.

주변 음식점을 검색한 뒤 선택한 음식점을 출발지 또는 도착지로 바로 지정하는 기능도 제공합니다.

## 프로젝트에서 문제와 해결 방법

### 서로 다른 좌표계를 일관되게 다루기

데이터의 출처마다 사용하는 좌표계가 달랐습니다. 경로 API는 위·경도 기반 좌표를, 음식점 데이터는 `EPSG:5174`를, OpenLayers 화면은 `EPSG:3857`을 사용했습니다. 좌표를 그대로 렌더링하면 마커와 경로가 실제 위치에서 벗어나는 문제가 발생할 수 있었습니다.

`proj4`에 `EPSG:5174` 정의를 등록하고 데이터가 UI에 진입하는 지점에서 목적 좌표계로 변환했습니다. 또한 지도 화면 범위 검색에서는 화면의 `EPSG:3857` extent를 API가 사용하는 `EPSG:4326` 경계 좌표로 변환해 전달했습니다.

```text
경로 API(EPSG:4326) ── fromLonLat ── OpenLayers(EPSG:3857)
음식점(EPSG:5174)   ── transform  ── OpenLayers(EPSG:3857)
지도 화면(EPSG:3857) ─ transformExtent  검색 API(EPSG:4326)
```

### 양방향 탐색 결과의 중첩 구간 판별하기

탐색 API의 각 결과에는 부모 좌표, 방문 좌표, 탐색 방향이 포함됩니다. 단순히 방향별 선을 그리면 정방향과 역방향 탐색이 만나는 지점을 알아보기 어려웠습니다.

좌표는 소수점 7자리 기준의 키로 정규화하고, 두 좌표로 이루어진 간선은 좌표 키를 정렬해 방향과 무관한 동일 간선으로 판별했습니다. 이후 각 좌표와 간선에 포함된 탐색 방향을 `Set`으로 수집해 `FORWARD`, `REVERSE`, `OVERLAP` 세 그룹으로 분류했습니다. 이 방식으로 양쪽 탐색이 공유한 간선뿐 아니라 공유 좌표에 연결된 구간도 중첩 영역으로 표현했습니다.

### 상세한 경로 데이터를 읽기 쉬운 안내 정보로 바꾸기

API가 반환하는 모든 직진 좌표를 그대로 목록에 노출하면 사용자가 확인해야 할 항목이 지나치게 많아집니다. 연속된 `STRAIGHT` 단계를 하나의 안내 구간으로 병합하고, 시작점부터 마지막 직진점까지의 누적 거리를 계산해 `직진 (320 m)` 형태로 표시했습니다.

경로 선과 안내 지점에 동일한 `routeInfo` 메타데이터를 연결하여, 지도에서 선택한 정보와 사이드바가 같은 데이터를 사용하도록 구성했습니다. Redux 상태를 통해 지도 호버·목록 호버·포커스 이동도 동기화했습니다.

### 지도 객체와 React 생명주기 연결하기

OpenLayers의 지도, 레이어, 오버레이는 명령형 객체이고 React는 선언형 렌더링을 사용합니다. 지도 객체를 렌더링마다 다시 생성하지 않도록 `useRef`로 보관하고, 초기화·이벤트 등록·정리를 `useEffect`에서 관리했습니다. API 결과가 변경될 때는 기존 VectorSource를 비우고 필요한 Feature만 다시 구성하도록 역할을 분리했습니다.

## 기술 선택 이유

| 기술          | 선택 이유 및 활용                                                   |
| ------------- | ------------------------------------------------------------------- |
| React         | 검색 UI, 지도 컨트롤, 오버레이, 사이드바를 컴포넌트 단위로 구성     |
| Redux Toolkit | API 결과와 지도·사이드바 간 선택, 호버, 포커스 상태를 일관되게 공유 |

| proj4         | `EPSG:5174`, `EPSG:4326`, `EPSG:3857` 좌표계 변환                   |
| Axios         | 경로 탐색 및 음식점 검색 REST API 연동                              |
| Tailwind CSS  | 지도 위 패널과 컨트롤 UI를 빠르게 구성하고 상태별 스타일 적용       |
| Vite          | 빠른 개발 서버와 프로덕션 번들 생성                                 |
